# Приватный бакет + presigned URLs для треков

Делает прямые ссылки на mp3 **временными** (TTL). Утечка ссылки из Network tab или
логов перестаёт давать доступ «навсегда»: без свежей подписи прямой GET → 403.

## Как это устроено в коде

- `audio_url` в БД по-прежнему хранит **публичный URL объекта** (схема B): миграция
  данных не нужна, старые записи продолжают работать.
- На каждый API-запрос с треками (`GET /orders/{id}`, `/orders/{id}/share`,
  `/orders/{id}/status`) handler вызывает `TrackStorage.ResolvePlayURL`, которая:
  - при `S3_PRESIGN_ENABLED=false` — возвращает сохранённый URL **как есть** (как раньше);
  - при `true` — извлекает ключ объекта из URL (`keyFromURL`, понимает CDN-базу и
    legacy S3-origin) и подписывает его на `S3_PRESIGN_TTL` (SigV4 presigned GET).
- Share-страница `/s/{uuid}` не меняется: каждый заход = новые подписи.
- В письме «песня готова» прямых mp3-ссылок больше нет — только ссылка на сайт
  (presigned-ссылка в письме всё равно протухла бы).
- **Демо (`demos/*`, `…/demo-*.mp3`) НЕ подписывается** и остаётся публичным. Демо —
  короткий тизер с водяным знаком (воронка хочет, чтобы его свободно слушали), а
  показывается оно на pending-заказе с активным опросом каждые 10с: подпись меняла
  бы ссылку на каждом опросе и сбрасывала бы воспроизведение демо. Приватность тут
  почти не даёт пользы. Presign применяется только к **финальным трекам**.

## Включение на проде (поэтапно)

1. **Staging сначала.** Выставить `S3_PRESIGN_ENABLED=true`, задеплоить.
2. **Сделать приватным только `tracks/*`:** убрать public-read ACL/policy с
   префикса `tracks/*`. Префиксы `demos/*` (и `covers/*`, `examples/*`) **оставить
   публичными** — демо это водяной-знак-тизер, presign его не трогает (см. выше и
   `deploy/CDN.md`).
3. **Проверить:**
   - `/s/{uuid}` — плеер играет все версии;
   - `/status/{uuid}` с токеном — плеер + скачивание работают;
   - прямой публичный URL вида `…/tracks/{id}/1.mp3` без подписи → **403**;
   - демо на pending-заказе играет без сбросов (его ссылка осталась публичной);
   - удаление заказа/демо из админки — без ошибок (delete идёт на S3-API, не зависит от presign);
   - share revoke (`share_revoked`) — `/s/{uuid}` по-прежнему 404.
4. Повторить на проде.

## Откат

`S3_PRESIGN_ENABLED=false` + вернуть public-read на `tracks/*` → задеплоить.
Старые public-URL в БД продолжат работать (их формат не менялся). Никакой
миграции данных откат не требует.

## Параметры

| Переменная | Дефолт | Назначение |
|---|---|---|
| `S3_PRESIGN_ENABLED` | `false` | включить presigned-ссылки на треки (нужен приватный бакет) |
| `S3_PRESIGN_TTL` | `24h` | срок действия подписанной ссылки (API/share/status) |

## Важно

- **CDN не используется для треков** в presign-режиме (приватный origin) — треки
  идут напрямую на S3-endpoint. CDN остаётся для обложек/примеров. Подробнее —
  `deploy/CDN.md`.
- Формат `X-Access-Token` в API **не менялся** — presign касается только выдачи
  ссылок на сами mp3.
