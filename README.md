## 📌 Кратко (Executive summary)

**Продукт.** Full-stack сервис, превращающий бриф клиента в готовую песню: нейросеть
пишет текст и музыку, фоновые воркеры оркеструют конвейер, фронтенд — премиальный
тёмный SPA с конструктором промптов, онлайн-плеером и каталогом из 30+ поводов.

**Бизнес-суть.** Один фиксированный платёж **990 ₽** (на витрине — рядом с
зачёркнутой прежней ценой 2 000 ₽) за **4 уникальные версии** песни. Перед оплатой
клиент бесплатно слушает **демо-фрагмент** своей будущей песни — воронка «сначала
послушай, потом плати» снимает главный барьер и кратно поднимает конверсию холодного
трафика.

**Экономика в одной строке.** Себестоимость заказа ≈ **75 ₽**, с налогом НПД (4%) ≈
**115 ₽**; чистая контрибуция ≈ **875 ₽ (~88%)**. Расход на бесплатные демо ограничен
сверху конфигом (≤ ~1 080 ₽/сутки) и стоит единицы процентов выручки. *(Числа
подтверждены фактическими ставками Robokassa, TTAPI и налогом НПД — см. «Юнит-экономика».)*

**Готовность.** ~**90%** к эксплуатации: реальные платежи Robokassa работают, инфра/
CI-CD/мониторинг/бэкапы развёрнуты, 827 Go-тестов + e2e, покрытие ≥70%.

## 🎯 Бизнес-модель

### Ценностное предложение
Персональная песня под конкретный повод — эмоциональный подарок, который нельзя
купить «с полки». Numaestra делает его **быстрым (10 мин), доступным (990 ₽) и
безрисковым (демо до оплаты)**.

### Рынок и сегменты (use-cases)
Событийный спрос «на повод»: свадьба, юбилей, день рождения, годовщина, признание в
любви, корпоратив, выпускной, детская песня, поздравление коллеге/боссу. 30+
категорий + конструктор «свой жанр» — длинный хвост поводов.

### Монетизация
| Параметр | Значение | Где задаётся |
|---|---|---|
| Модель | разовый платёж, **без подписок** | `PRICE_KOPECKS` |
| Цена | **990 ₽** за 4 версии | `PRICE_KOPECKS=99000` |
| Якорная цена | зачёркнутое **2 000 ₽** рядом с текущей ценой | `OLD_PRICE_KOPECKS=200000` |
| Цену задаёт | **сервер** (клиент не может занизить) | `usecase.CreateOrder` |
| Демо | **бесплатно**, 1 короткий фрагмент с водяным знаком | `DEMO_*` |
| Допродажи (потенциал) | постер/QR/слайд-шоу, ускоренная очередь | — (roadmap) |

### Конкурентное преимущество — воронка «demo-first»
Прямые конкуренты берут предоплату «вслепую». Numaestra отдаёт демо **до** платежа:
клиент слышит результат заранее. Это:
- **Снижает CAC** — холодный трафик конвертит без барьера предоплаты.
- **Поднимает конверсию** — оплачивает тот, кто уже эмоционально зацепился.
- **Защищено по стоимости** — демо = 1 дешёвая задача, расход ограничен сверху (см.
  «Экономическая безопасность»).

## 💰 Юнит-экономика

> Параметры делятся на **фиксированные** (из кода/конфига, точные) и **допущения**
> (рыночные ставки — ⚠️ подставьте свои). Все расчёты даны формулами, чтобы модель
> пересчитывалась под ваши числа.

### Фиксированные параметры (из кода)
| Символ | Смысл | Значение |
|---|---|---|
| `P` | цена заказа | **990 ₽** |
| `T_paid` | задач Suno на платный заказ (2 текста × 2 интерпретации = 4 клипа) | **2** |
| `T_demo` | задач Suno на демо (1 клип) | **1** |

### Измерено по факту (реальные данные Robokassa + TTAPI)
| Символ | Смысл | Значение | Источник |
|---|---|---|---|
| `pay_cost` | эквайринг Robokassa + вывод на карту | **6,0% ≈ 59 ₽** | замерено на чеке 2000: → 1930 (−3,5%) → 1880 (−2,5%) |
| `q` | стоимость 1 квоты TTAPI | **$0,01** | баланс 922 квоты ≈ $9,22 |
| `c_suno` | 1 задача Suno = 6 квот | **$0,06 ≈ 5,4 ₽** | по 6 квот/задачу, курс e≈90 ₽/$ |

### Налог (НПД, B2C-клиенты-физлица)
| Символ | Смысл | Значение |
|---|---|---|
| `t` | ставка НПД (с физлиц), база = вся сумма чека `P` | **4%** (первые ~1000 заказов — **3%** по вычету 10 000 ₽) |
| `tax` | налог на заказ | `t · P` ≈ **40 ₽** (бонусная фаза — ~30 ₽) |

> Комиссии Robokassa в НПД **не вычитаются** (налог с оборота). На **ИП УСН 6%** при
> росте: `tax ≈ 59 ₽`, взносы зачитываются в налог — см. «Налоги и юр. форма».

### Допущения (⚠️ подставьте свои)
| Символ | Смысл | Принято |
|---|---|---|
| `e` | курс ₽/$ | **≈ 90 ₽/$** ⚠️ |
| `c_misc` | S3-хранение + перезалив + email на заказ | **≈ 5 ₽** ⚠️ |
| `R` | конверсия демо → оплата | **15–30%** ⚠️ |

### Себестоимость платного заказа (переменная + налог), при e=90, НПД 4%
```
COGS = pay_cost  +  tax   +  T_paid · c_suno  +  c_misc
     = 59,4      +  39,6  +  2 · 5,4          +  5
     = 59,4      +  39,6  +  10,8             +  5   ≈  115 ₽
```

### Чистая контрибуция на заказ
```
CM₀ = P − COGS = 990 − 115 = 875 ₽   →   ~88%
(без налога — 915 ₽ / 92%; налог НПД 4% забирает ~40 ₽)
```

### Стоимость демо как канал привлечения (CAC через демо)
Демо тратит 1 задачу Suno (~5,4 ₽) на **каждого**, кто его получил, включая не купивших.
Затраты на демо в пересчёте на **одну продажу**:
```
CAC_demo = c_suno / R = 5,4 / R
   R=30% → 18 ₽     R=20% → 27 ₽     R=15% → 36 ₽
```

### Контрибуционная маржа на продажу (с учётом демо), НПД 4%
```
CM = CM₀ − CAC_demo = 875 − 5,4/R
   R=30% → 857 ₽     R=20% → 848 ₽     R=15% → 839 ₽
```
**Маржа остаётся ~85%+ в любом разумном сценарии конверсии.** Демо стоит копейки
(≈5,4 ₽). Главные статьи себестоимости — **эквайринг+вывод (~59 ₽)** и **налог (~40 ₽)**;
AI (Suno) — почти невесом (~11 ₽). Сократить можно эквайринг/вывод (вывод на ИП-счёт
обычно дешевле карты) — не AI.

## 📈 Финансовая модель

### Стоимость владения (OPEX, в месяц)
| Статья | Тип | Оценка |
|---|---|---|
| VPS (app + worker + Postgres + Redis + monitoring) | фикс | 2 000–5 000 ₽ |
| S3 (Yandex Object Storage, хранение+egress) | ~перем. | 100–500 ₽ |
| SMTP (rusender) | ~перем. | сотни ₽ |
| Домен | фикс (амортизация) | ~150 ₽ |
| TLS (Let’s Encrypt via Caddy) | — | 0 ₽ |
| Мониторинг (self-hosted Prometheus+Alertmanager) | — | 0 ₽ |
| Suno-кредиты (TTAPI) | перем. | `≈10,8 ₽ · заказы + 5,4 ₽ · демо` (e=90) |
| Эквайринг + вывод Robokassa | перем. | `6,0% · выручка` (3,5% эквайринг + 2,5% вывод) |
| Налог (НПД 4% / УСН ~6%) | перем. | `4% · выручка` (НПД) или `~6%` (УСН при росте) |
| **Фикс. итого** | | **≈ 3 000–8 000 ₽/мес** + переменные |

> ⚠️ **Баланс TTAPI пополняется заранее** (не постоплата): 922 квоты ≈ 76 заказов /
> 153 демо. На потоке — мониторинг и автопополнение кредитов.

### Точка безубыточности (покрытие инфраструктуры)
```
BE_orders = F_fixed / CM ≈ 7 500 / 848 ≈ 9 заказов/мес
```
Инфраструктура окупается **первым десятком заказов**; дальше всё — в прибыль и
маркетинг.

### Сценарии выручки (в месяц), с налогом и демо (R=20%)
| Заказов/мес | Режим | Выручка | Контрибуция | CM/заказ |
|---|---|---|---|---|
| 100 | НПД 4% | 99 000 ₽ | ~84 800 ₽ (~86%) | 848 ₽ |
| 500 | УСН 6% | 495 000 ₽ | ~414 000 ₽ (~84%) | 828 ₽ |
| 1 000 | УСН 6% | 990 000 ₽ | ~828 000 ₽ (~84%) | 828 ₽ |
| 3 000 | УСН 6% | 2 970 000 ₽ | ~2 484 000 ₽ (~84%) | 828 ₽ |

> Контрибуция = выручка − эквайринг/вывод (6%) − **налог** − Suno (заказы+демо) − прочее.
> При R=20% на 1 продажу приходится 5 демо (5·5,4 ≈ 27 ₽ — копейки против маржи).
>
> ⚠️ **Лимит НПД — 2,4 млн ₽/год (~200 заказов/мес).** Сценарии 500+ заказов/мес
> требуют **ИП на УСН 6%** (налог ~59 ₽/заказ вместо ~40 ₽, контрибуция ~828 ₽).

### Налоги и юр. форма
| Форма | Ставка | Взносы | Лимит выручки | Когда |
|---|---|---|---|---|
| **Самозанятый / ИП на НПД** | 4% с физлиц (3% первые ~1000 заказов по вычету 10 000 ₽) | **нет** | **2,4 млн ₽/год** (~200 зак/мес) | старт |
| **ИП на УСН «Доходы»** | ~6% | обязательные **~57k ₽/год** + 1% свыше 300k (зачитываются в налог) | ~265 млн ₽/год | рост >200 зак/мес |

- **НПД:** нет взносов, нет онлайн-касс, нет отчётности; чеки клиентам готовит
  приложение, ФНС видит платежи сама. На паузе бизнеса — 0 обязательных платежей.
- **УСН:** взносы обязательны (даже на паузе), но у ИП без работников **уменьшают
  налог** — на потоке эффективная ставка ≈ 6%.
- **Рекомендация:** старт — **ИП на НПД** (сохраняет все льготы выше). Переход на УСН —
  при выходе за лимит 2,4 млн ₽/год. Разница в марже ~88% → ~86%.

### Окупаемость разработки
Стоимость постройки такой кодовой базы — **≈ 3–6 млн ₽** (senior-уровень: платежи,
AI-оркестрация, аудио-пайплайн, гексагональная архитектура, ≥70% покрытие, CI/CD,
мониторинг). При **500 заказов/мес** (≈414k вал. прибыли) окупаемость —
**~8–15 месяцев** в зависимости от маркетинг-бюджета.

### LTV / CAC
- Продукт событийный (разовый), но новые поводы дают повтор: **LTV ≈ 1,2–1,5 · P ≈
  1 200–1 500 ₽**.
- Здоровый ориентир: **CAC < LTV/3 ≈ 400–500 ₽**.
- Воронка demo-first структурно снижает CAC относительно модели «предоплата вслепую».

## 🛡️ Экономическая безопасность (риск = код)

Ключевые финансовые риски закрыты не регламентом, а **кодом и конфигом** — параметры
управляют экономикой в рантайме без передеплоя логики.

### Потолок расхода на демо (защита от «демо-DDoS»)
```
Макс. дневной burn = DEMO_DAILY_LIMIT · c_suno = 200 · 5,4 ≈ 1 080 ₽/сутки  (≈ 32k ₽/мес — худший случай при атаке)
```
Это **известный, застрахованный потолок**. Реальный расход на порядок ниже за счёт
многоуровневой защиты:

| Уровень | Параметр | От чего |
|---|---|---|
| Стоимость | `DEMO_DAILY_LIMIT=200` + `DEMO_TOKEN_RESERVE=10` | разорение / голод платных |
| Источник | `DEMO_PER_IP_DAILY=5` | выжигание бюджета одним источником |
| Контакт | `DEMO_PER_EMAIL_HOURS=24` | наивный спам |
| Запрос | Idempotency-Key + rate-limit 60/мин | двойные клики, флуд |
| Приоритет | очередь `demo` (вес 1) | демо не отбирает аккаунт у платных |

> **Резерв токенов** гарантирует: демо никогда не съест кредиты, забронированные под
> платные заказы. **Платный поток финансово неуязвим для демо-абуза.**

### Целостность платежей (защита выручки)
- Идемпотентные вебхуки + защита от replay (Redis-нонс) — нет двойных списаний/
  генераций.
- Сверка суммы (копейка-в-копейку, строковый разбор) — нельзя занизить платёж.
- **Cron-реконсиляция** «оплачено, но вебхук не дошёл» — деньги не теряются, даже если
  IP-allowlist Robokassa сменился.
- Recovery застрявших заказов и слотов аккаунтов — оплаченный заказ всегда доходит до
  результата.

## 🔄 Как это работает (demo-first)

```
Клиент → бриф/конструктор ─▶ POST /orders ─▶ заказ создан (pending)
                                   │                 │
                                   │        TriggerDemo (best-effort, лимит на IP)
                                   ▼                 ▼
                          страница /status ◀── демо готовится (1 задача Suno)
                                   │
              слушает бесплатное демо ─▶ «Перейти к оплате» ─▶ Robokassa
                                                                   │
                                       webhook оплаты ◀────────────┘
                                              │
                                   Asynq/Redis очередь (вес: generation 5, polling 5, demo 1)
                                              │
   воркер: захват Suno-аккаунта → промпт → 4 версии → перезалив в S3 → уведомление
                                              │
   Клиент ◀── GET /orders/{id} (X-Access-Token) ── статус + 4 трека (без водяного знака)
```

**Маршрут клиента:** собрать запрос (категория-квиз или конструктор: жанр/настроение/
темп/вокал, до 3 своих жанров) → email → **бесплатное демо на /status** → оплата (если
понравилось) → 4 версии за ~10 минут → плеер, скачивание, шеринг. Ссылки — навсегда.

Архитектура — гексагональная: `domain` → `usecase` → `delivery`/`repository`/`worker`,
внешние интеграции изолированы в `pkg/`.

## 🚀 Быстрый старт (всё в Docker)

Образ `app` многоступенчатый: Node собирает SPA → SPA встраивается в Go-бинарник,
который раздаёт и API, и фронтенд на одном порту.

```bash
docker compose up -d --build
```

Открой **http://localhost:8080** (главная) и **/admin/login** (админка). Миграции
(включая сидинг категорий) применяются автоматически. Здоровье:

```bash
curl http://localhost:8080/healthz   # {"status":"ok","checks":{"postgres":"ok","redis":"ok"}}
```

## 🛠️ Локальная разработка

Понадобятся **Go 1.26+**, **Node 20+**, **Docker** (и `ffmpeg` для демо Фазы 2).

```bash
docker compose up -d postgres redis   # инфраструктура
make dev                              # бэкенд + фронтенд (нужны GNU make + bash)
```

Либо по отдельности: `go run ./cmd/server` (API :8080 + воркер, авто-миграции) и
`make frontend-dev` (Vite :3000, проксирует `/api` → :8080).

Полезное (`make help`): `make test` / `make test-race` / `make lint` /
`make frontend-check` (lint + typecheck + vitest + build).

## ⚙️ Конфигурация

Дефолты в `internal/config/config.go` совпадают с docker-compose, поэтому для dev
`.env` не обязателен. **Обязательны для прода** (`APP_ENV != dev`, иначе фатальная
ошибка при старте): `ADMIN_TOKEN`, `ADMIN_LOGIN`/`ADMIN_PASSWORD`,
`ADMIN_SESSION_SECRET`, `SUNO_API_KEY`, `REDIS_PASSWORD`, `SESSION_ENCRYPTION_KEY`,
`S3_ACCESS_KEY`/`S3_SECRET_KEY`, корректные `ROBOKASSA_*`. Рекомендуется `SMTP_HOST`.

## 🌐 HTTP API (выдержка)

| Метод | Маршрут | Доступ | Назначение |
|-------|---------|--------|------------|
| `POST` | `/api/v1/orders/` | публичный (Idempotency-Key) | Создать заказ + триггер демо |
| `POST` | `/api/v1/orders/webhook/robokassa` | подпись Robokassa | Подтверждение оплаты (идемпотентно) |
| `POST` | `/api/v1/orders/{id}/sync-payment` | публичный | Сверка оплаты через OpStateExt |
| `GET` | `/api/v1/orders/{id}` | `X-Access-Token` | Статус, демо, треки |
| `GET` | `/api/v1/orders/{id}/status` | публичный | Публичный статус (для возврата с оплаты) |
| `GET` | `/api/v1/promo/{code}` | публичный | Проверка промокода |
| `GET` | `/api/v1/categories/{id}/wizard` | публичный | Квиз категории |

Публичные маршруты защищены rate-limiting по IP и CORS.

## 🔐 Админка

`/admin` — заказы (возврат через Robokassa, обратная связь), пул Suno-аккаунтов,
категории/жанры/примеры/отзывы/промокоды, **дашборд с воронкой демо→оплата**. Вход по
`ADMIN_LOGIN`/`ADMIN_PASSWORD` → httpOnly + Secure + SameSite=Strict cookie с
HMAC-SHA256-токеном (без серверного состояния). Для CI/скриптов — `ADMIN_TOKEN` как
`Authorization: Bearer`.

## 🚢 Продакшен (VPS / Docker Compose)

> 📦 **Деплой и CI/CD** — в [DEPLOY.md](DEPLOY.md): CI собирает образ → push в GHCR →
> авто-деплой по SSH. Прод тянет готовый образ (`docker-compose.prod.yml`).

# Прод: только базовый файл (без dev-override), наружу торчит лишь Caddy (80/443)

алертов (`ALERT_EMAIL_TO` и/или `TELEGRAM_*`) — иначе `deploy/deploy.sh` остановит выкладку.
